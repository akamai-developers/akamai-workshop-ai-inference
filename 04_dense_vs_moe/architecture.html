Module 4  ·  Why decode is memory-bound
To make one token, the server reads every weight once. So decode is capped by how fast the card reads memory, not by how much math it can do.
Decode reads all the weights

One token, every weight. It sits far down the memory side, using a fraction of a percent of the card's compute.

Prefill does a lot of math per byte

It reads the prompt once and reuses each weight across many tokens, so it sits near the compute ceiling.

MoE reads fewer weights

A Mixture-of-Experts model routes each token to a few experts, so it moves far fewer bytes per token than its total size.

RTX 4000 Ada: about 107 TFLOP/s dense FP16 over 360 GB/s, so the ridge point sits near 297 FLOPs per byte. Quantization, FlashAttention, speculative decoding, and batching are four more ways to beat the memory limit.
